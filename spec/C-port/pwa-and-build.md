# Offline app and builds

Part of the [specification](../README.md), part C: GoldBox Rerolled. **Normative.** The installable
offline web app (IMP-005, [IMPROVEMENTS.md](../../IMPROVEMENTS.md)), the single-file build, the
version stamp, and the parts of the Docker image other things depend on. Port behaviour, observed in
the reference implementation (`web/vite.config.ts`, `web/src/pwa/`, `web/src/version.ts`,
`Dockerfile`), normative as written; **I** marks what follows from the tools used rather than from
the project's own code. Running the image is the operator's guide
[docs/server.md](../../docs/server.md) (informative).

## 1. Builds

| Build | Command (in `web/`) | Output | Service worker |
|---|---|---|---|
| Web app (PWA) | `npm run build` (`tsc && vite build`) | `web/dist/` | yes |
| Single file | `npm run build:single` (`tsc && vite build --mode single`) | `web/dist-single/index.html` | no |
| Development | `npm run dev` (`vite`) | served from memory | no (**I**: the PWA plugin's default) |

Both builds first type-check the whole project, the server included. Neither contains game data
(CLAUDE rule 4); the only data files they ship are the port's own: the favicon and the journal's map
scans (`journal/*.png`, CC BY-SA, IMP-055).

- **`dist/`** holds `index.html`, `assets/` (the JavaScript and CSS bundles, named by content hash;
  the exploration and camp screens are separate chunks loaded when first needed), `favicon.svg`,
  `journal/*.png`, `manifest.webmanifest`, `sw.js` and its Workbox runtime.
- **`dist-single/index.html`** has every script and style inlined, so the one file runs from disk
  (`file://`) or any web server. `favicon.svg` and `journal/` are copied beside it; without them the
  journal shows its text and no maps. This build registers no service worker (one cannot run from
  `file://`): its `virtual:pwa-register` is replaced by a stub whose registration does nothing. With
  no server beside it the account controls stay hidden ([accounts-and-sync.md §5.11](accounts-and-sync.md#511-finding-the-server-and-the-status)).
  Whether IndexedDB, and so the game import, works from `file://` is up to the browser (**?**).

## 2. Base path

The builds use the base `./`: every URL in `index.html` and the bundles is relative to the page, so
a build works at any path (a site's root, a sub-folder, a file on disk) without being rebuilt. The
manifest's `start_url` and `scope` are `./`; the journal images are loaded from `<base>journal/…`;
the API is found relative to the page ([accounts-and-sync.md §2.1](accounts-and-sync.md#21-transport)).
The GoldBox Rerolled server itself serves the app at `/`; under a sub-path it needs a proxy that
removes the prefix (**I**).

## 3. The manifest

`manifest.webmanifest`, linked from `index.html`:

| Field | Value |
|---|---|
| `name`, `short_name` | `GoldBox Rerolled` |
| `description` | `The SSI Gold Box games in the browser. Bring your own game files.` |
| `start_url`, `scope` | `./` |
| `display` | `standalone` |
| `background_color`, `theme_color` | `#101820` |
| `lang` | `en` |
| `icons` | one: `favicon.svg`, `sizes: any`, `type: image/svg+xml`, `purpose: any` |

`index.html` carries the same theme colour (`<meta name="theme-color" content="#101820">`), the
viewport `width=device-width, initial-scale=1.0, viewport-fit=cover`, the SVG icon and the title
`GoldBox Rerolled`; the title becomes `GoldBox Rerolled: <game name>` while a game is open.

## 4. The service worker

`sw.js`, generated by Workbox through `vite-plugin-pwa` in **prompt** mode, registered on every page
load of the PWA build:

- **Precache**: every built file matching `**/*.{js,css,html,svg}` and `journal/*.png`, and the
  manifest, each with a content revision. Nothing else is cached: no game files (they are in
  IndexedDB, [storage.md §2](storage.md#2-the-game-files-database)) and no API responses. Caches of
  older versions are deleted when a new worker activates.
- **Navigation**: a navigation request is answered with the precached `index.html`, **except** a URL
  matching `/\/api\//`, which goes to the network. This matters for *Download my data*, a navigation
  to `api/v1/export` ([accounts-and-sync.md §4.5](accounts-and-sync.md#45-the-data-export)) that would
  otherwise get the app's page.
- **Everything else** (API calls by `fetch`, any file not precached) goes to the network untouched.
- **Updates**: the browser checks `sw.js` on navigation (the server sends it, `index.html` and the
  manifest as `no-cache`, [accounts-and-sync.md §7](accounts-and-sync.md#7-serving-the-app-and-security-headers)).
  A new worker installs and waits. The page then shows a bar, fixed at the bottom centre:
  **"A new version is available."** with **Reload** and **Later**. Reload tells the waiting worker
  to take over (the message `{ type: "SKIP_WAITING" }`) and reloads the page once it has; Later
  removes the bar, and the new version starts when every tab of the app has been closed. The page
  never reloads by itself.

## 5. Offline behaviour

- The first visit needs the network. After it, the PWA build starts with no network at all, and the
  single file never needs one.
- At run time the app makes **no request outside its own origin**: fonts, libraries (three.js) and
  styles are in the bundle, the game font and window frames are built in the browser from the
  player's files, and the server's CSP enforces this
  ([accounts-and-sync.md §7](accounts-and-sync.md#7-serving-the-app-and-security-headers)).
- The game files are imported once and kept ([storage.md §2](storage.md#2-the-game-files-database));
  play, saving, export and import work offline. With an account, changes queue until the server is
  reachable ([accounts-and-sync.md §5](accounts-and-sync.md#5-client-sync)).

## 6. The version stamp

Fixed at build time as `{ commit, dirty, date }`:

- `commit`: the environment variable `GIT_COMMIT` when set and not empty, else
  `git rev-parse --short HEAD`, else `unknown`;
- `dirty`: true when `GIT_COMMIT` is not set and `git status --porcelain --untracked-files=no`
  prints anything (tracked files differ from the commit);
- `date`: the build's date, UTC, `YYYY-MM-DD`.

Shown as **`GoldBox Rerolled · version <commit>[ + local changes] · built <date>`** at the foot of
the games screen and in Settings (IMP-073). A commit of 7 to 40 hexadecimal digits links to
`https://github.com/tgreaves/goldbox-rerolled/commit/<commit>` (new tab). The Docker build has no
`.git`, so it shows `version unknown` unless `GIT_COMMIT` is passed in (§7). Code run without a build
(the tests) shows `version dev`.

## 7. The Docker image

One image holds the built app and the server ([accounts-and-sync.md](accounts-and-sync.md)). The
contract other things rely on:

| | |
|---|---|
| Build | from the repository root, two stages on `node:24` (Alpine): `npm ci` and `npm run build` in `web/`, then the runtime |
| Build argument | `GIT_COMMIT` (default `unknown`): the version stamp's commit (§6) |
| Contents | `server/*.ts` and `web/dist` only, under `/app`; no game files, no secrets; no npm packages at run time (Node runs the TypeScript directly) |
| User | the unprivileged `node` user |
| Command | `node server/main.ts` |
| Environment | the server's variables ([accounts-and-sync.md §8](accounts-and-sync.md#8-configuration)), preset to `PORT=8080`, `HOST=0.0.0.0`, `DATA_DIR=/data`, `WEB_ROOT=/app/web/dist`, `COOKIE_SECURE=1`, `TRUST_PROXY=0`, `SIGNUP=open`, `MAX_USERS=1000`, `QUOTA_MB=20`, and `NODE_ENV=production` |
| Volume | `/data`: every account and record; the only place the server writes, so the root file system can be read-only |
| Port | 8080 |
| Health check | every 30 s (timeout 5 s, start period 10 s, 3 retries): `GET http://127.0.0.1:$PORT/api/v1/health`, healthy on a 2xx answer |

The build context leaves out `.git`, `docs/`, `spec/`, `tools/`, game files and players' data
(`.dockerignore`). `docker-compose.yml` and `deploy/Caddyfile` are **examples** (informative): the
app with a named volume on `/data`, `COOKIE_SECURE=1` and `TRUST_PROXY=1`, published on 127.0.0.1
only, read-only root with a `/tmp` tmpfs, no capabilities, `no-new-privileges`, rotated logs; and,
under the `proxy` profile, Caddy terminating HTTPS for `$DOMAIN` and passing requests to the app with
bodies limited to 10 MB.

## Validation

- `web/test/server.test.ts`, "serves the app with MIME types and PWA cache rules": `index.html`,
  `sw.js` and the manifest revalidated, hashed assets immutable.
- The builds are checked by building them; the offline start and the update bar by hand in a browser
  (to be recorded in [VALIDATION.md](../VALIDATION.md)).
